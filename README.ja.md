# excel-konva

**Konva** と **RxJS** を用いた、エンジニアリング指向の Excel 風スプレッドシート実装です。

## 概要

`excel-konva` は、**命令的な Canvas 描画（Konva）** と **リアクティブな状態管理（RxJS）** を組み合わせ、Excel ライクなグリッド UI を構築するための実験的プロジェクトです。

機能の網羅性よりも、**アーキテクチャ設計・描画モデル・性能特性**を重視しています。

## 目的

- Canvas ベース表計算 UI の設計検証
- RxJS を用いたイベント／状態モデルの検討
- エディタ系 UI の基盤アーキテクチャ提供

対象外：

- Excel の完全再現
- 数式エンジンや永続化機構

## アーキテクチャ

```
┌───────────────┐
│ 入力層        │ マウス / キーボード
└─────┬─────────┘
      │
┌─────▼─────────┐
│ RxJS イベント │ 選択 / スクロール / 編集
│ ストリーム    │
└─────┬─────────┘
      │
┌─────▼─────────┐
│ 状態モデル    │ ビューポート / セル
└─────┬─────────┘
      │
┌─────▼─────────┐
│ Konva 描画    │ Rect / Text / Layer
└───────────────┘
```

### レイヤー構成

- **描画レイヤー（Konva）**
  - 描画責務のみを担当
- **状態・イベント（RxJS）**
  - セル状態とユーザー操作
- **制御層**
  - 状態変化を描画命令に変換

## パフォーマンス特性

- 描画コストは可視ピクセル数に依存
- 巨大グリッドはビューポートで制御
- 大きなノードのキャッシュを回避
- レイヤー分離による hit-test 最適化

## 設計上の判断

### Konva を採用した理由

- レイヤーと描画順の明確な制御
- エディタ系 UI に適した抽象化

### RxJS を採用した理由

- イベントと状態の明確な分離
- 予測可能な更新フロー

### DOM ベースを採用しない理由

- 大規模テーブルでは DOM の負荷が高い
- Canvas の方が性能特性を制御しやすい
