# excel-konva

一个基于 **Konva** 与 **RxJS** 的工程化 Excel 风格表格实现示例。

## 项目概述

`excel-konva` 是一个基于 Canvas 的电子表格原型项目，旨在探索如何使用 **命令式渲染（Konva）** 与 **响应式状态管理（RxJS）** 构建类似 Excel 的网格系统。

该项目更关注**架构设计、渲染模型与性能取舍**，而非功能完整性。

## 项目目标

- 验证 Canvas 方案在表格类应用中的可行性
- 探索基于 RxJS 的事件与状态建模方式
- 为编辑器 / 表格 / 网格系统提供基础架构参考

非目标：

- 完整的 Excel 功能
- 公式系统或持久化存储

## 架构设计

```
┌──────────────┐
│ 输入层       │ 鼠标 / 键盘
└─────┬────────┘
      │
┌─────▼────────┐
│ RxJS 事件流  │ 选择 / 滚动 / 编辑
└─────┬────────┘
      │
┌─────▼────────┐
│ 状态模型     │ 视口 / 单元格 / 选区
└─────┬────────┘
      │
┌─────▼────────┐
│ Konva 渲染   │ Rect / Text / Layer
└──────────────┘
```

### 核心分层

- **渲染层（Konva）**
  - 仅负责绘制
  - 不直接持有业务状态
- **状态与事件层（RxJS）**
  - 单元格数据
  - 交互与选择状态
- **协调层**
  - 将状态变化映射为绘制操作

## 性能说明

- Canvas 渲染成本与**可视像素**相关，而非逻辑网格大小
- 超大表格通过视口裁剪控制绘制范围
- 避免对大尺寸节点使用 cache
- 通过 Layer 分离降低命中检测成本

## 设计决策说明

### 选择 Konva 的原因

- 明确的层级与绘制控制
- 适合编辑器类应用
- 可预测的性能模型

### 选择 RxJS 的原因

- 明确区分事件流与状态流
- 状态更新路径清晰可控
- 避免隐式响应式带来的复杂性

### 不使用 DOM 表格的原因

- 大规模表格下 DOM 成本高
- Canvas 在性能与一致性上更可控
